Hoja de ruta02
02 / EncuadreEl plano

¿Qué es una arquitectura de datos?

Es el plano que define qué datos existen, dónde se guardan, cómo se mueven, quién los usa y con qué reglas. No es un software: es una decisión de diseño.

Clave

plano ≠ ladrillo

El plano no es la casa; la arquitectura no es la herramienta. Las herramientas implementan el diseño.

Concepto03
02 / EncuadreTres preguntas

Tres preguntas que responde la arquitectura

¿Dónde vive?

Dónde se guarda cada dato y en qué forma. Responde el almacenamiento.

¿Cómo se mueve?

Cómo se transforma y circula. Responde el procesamiento.

¿Quién lo usa?

Quién puede usarlo y con qué reglas. Responden el acceso y la gobernanza.

Concepto04
03 / DiseñoPor qué importa

Decidir sin arquitectura tiene consecuencias

Silos

Cada área guarda "su" dato y nadie ve el conjunto.

Duplicación

El mismo dato se captura varias veces, con valores distintos.

Desconfianza

Cada reporte cuenta una historia distinta y se pierde credibilidad.

Y la institución no puede crecer: sumar una fuente o un servicio obliga a reconstruir todo desde cero. Diseñar es barato; reparar una arquitectura improvisada es caro.

03 / DiseñoSíntomas

Cómo se nota una mala arquitectura

SíntomaEjemplo en gestión pública
El mismo dato, valores distintosEl padrón de contribuyentes no coincide entre Recaudaciones y Catastro.
Datos encerrados por áreaEl reclamo vive solo en la herramienta que lo originó.
Reportes lentos o manualesExportar y copiar en Excel durante días.
Cambios traumáticosMigrar un sistema paraliza a la institución.
Reglas poco clarasNo se sabe quién es dueño del dato ni quién lo corrige.

Componentes07
04 / Componentes1 de 4

1. Almacenamiento

Responde ¿dónde vive el dato y en qué forma? Bases de datos, data warehouse, data lake y archivos. Guarda datos estructurados (tablas) y no estructurados (documentos, imágenes).

Ejemplo

BD de trámites + escaneos

La base de datos de trámites junto al repositorio de documentos escaneados del municipio.

Componentes08
04 / Componentes2 de 4

2. Procesamiento

Responde ¿cómo se mueven y transforman los datos? Limpieza, unión y cálculo de indicadores. Puede ser por lotes (batch, cada noche) o en tiempo real (streaming).

Ejemplo

pagos del día → reporte

Cada noche se consolidan los pagos del día para actualizar el reporte de recaudación.

Componentes09
04 / Componentes3 de 4

3. Catálogo de datos

Responde ¿qué datos existen y qué significan? Documenta cada dato: definición, formato, dueño y origen. Incluye metadatos, como el diccionario de datos.

Ejemplo

"DNI" = identificación oficial

Un diccionario que define qué es el DNI, con su formato y el área responsable.

Componentes10
04 / Componentes4 de 4

4. Gobernanza

Responde ¿quién puede usarlo y con qué reglas? Define calidad, seguridad, privacidad, responsabilidad y acceso. Establece los dueños del dato.

Ejemplo

acceso con autorización

Solo el área de personal modifica el sueldo; ver datos personales exige autorización.

Componentes11
05 / FlujoDe la fuente al uso

Los componentes forman un flujo

Fuente

Sistemas, formularios y sensores donde nacen los datos.

→
Almacenamiento

Los datos se guardan en bases, warehouse o lake.

→
Procesamiento

Se limpian, unen y transforman para el análisis.

→
Uso

Quedan disponibles para reportes y decisiones.

El catálogo y la gobernanza no son una etapa: son capas transversales que atraviesan todo el flujo.

Referencia · Bloque 3 — Arquitectura de Datos

Patrones de arquitectura

Hoja de referencia rápida: qué guarda cada patrón, para qué sirve y qué riesgo trae.

La pregunta que decide

Pregunta para qué se usan los datos (reportes confiables, guardar todo, ambos), cuánto volumen hay, qué estructura tienen y si se necesitan en tiempo real. El patrón sale de esas respuestas.

PatrónQué guardaFoco principalTiempo realRiesgo o costo
Data warehouseDatos procesados y limpiosReportes confiablesNoPoco flexible ante datos nuevos
Data lakeDatos crudos y diversosGuardar todoNoSin gobierno se vuelve un pantano de datos
Data lakehouseCrudo + esquema y gobiernoAnalizar ambos mundosParcialExige más herramientas y madurez
LambdaBatch + velocidadReportes y alertasSíDos lógicas que mantener; mayor complejidad

Por qué importa: no hay un patrón mejor; hay un patrón adecuado para cada caso. Elegir por moda agrega complejidad y costo sin beneficio.

Para llevar

Warehouse → datos limpios para reportar.  ·  Lake → todo crudo, flexible.  ·  Lakehouse → crudo + esquema y gobierno.  ·  Lambda → lote + tiempo real.

Fuentes: Joyanes, Ciencia de Datos; Kimball & Ross, The Data Warehouse Toolkit; Kleppmann, Diseño de aplicaciones con uso intensivo en datos.

Consideraciones04
03 / ConsideracionesFrecuencia y volumen

¿Cada cuánto y cuánto?

Frecuencia — ¿cada cuánto?

Determina el método (batch vs. streaming) y la periodicidad. La nómina se procesa una vez al mes; los reclamos, varias veces al día.

Volumen — ¿cuánto?

Determina el esfuerzo y la técnica para no saturar. Consolidar 500 registros mensuales es trivial; miles de medidores cada hora exigen otro diseño.

Consideraciones05
03 / ConsideracionesFiabilidad

¿Qué pasa si falla?

Determina las garantías que debe tener la ingesta. ¿Se puede repetir sin duplicar? ¿Sabemos si algo no llegó?
Idempotencia: repetir una carga no debe producir datos duplicados ni corrompidos.

Ejemplo

Si la carga nocturna falla y se reintenta, el informe no debe contar dos veces la misma recaudación.

Patrones07
04 / PatronesCompleta vs. incremental

Todo o solo lo nuevo

Carga completa (full load)

Se mueve todo el conjunto, cada vez, reemplazando lo anterior. Cuándo: volúmenes pequeños o datos que cambian por completo. Ejemplo: un catálogo de códigos de trámites que se recarga entero cada mes.

Carga incremental

Se mueve solo lo nuevo o lo modificado desde la última carga. Cuándo: volúmenes grandes y crecientes. Ejemplo: cada día se agregan solo los trámites nuevos, no toda la historia.

Patrones08
04 / PatronesCDC · pull · push

Cambios exactos y quién inicia

Captura de cambios (CDC)

La propia fuente registra y entrega solo los cambios (altas, bajas, modificaciones). Cuándo: saber exactamente qué cambió, casi en tiempo real. Ejemplo: el registro civil emite eventos al actualizar un dato.

Pull vs. push

Pull: nuestro sistema va a buscar los datos (un script que consulta una API cada noche). Push: la fuente nos envía los datos cuando hay novedades (una API que notifica un reclamo).

06 / PipelineDefinición

¿Qué es un pipeline de ingesta?

La secuencia repetible que lleva los datos desde la fuente hasta el destino. Integra todo el bloque: método (batch/streaming), herramienta (script/conector/API) y patrón (completa/incremental/CDC).

Un pipeline funcional se puede volver a correr mañana y produce lo mismo, sin duplicados ni pérdidas.

08 / En la prácticaTaller

Implementar el pipeline

1. Diseña

En parejas o equipos de 2–3, respondan frecuencia, volumen y fiabilidad y elijan un patrón.

2. Construye

Implementen extraer → transformar → cargar → verificar sobre la fuente CSV asignada.

3. Verifica

Prueben el pipeline, corrijan lo que falle y documenten qué hace cada etapa.

Cada equipo demuestra su pipeline al grupo.

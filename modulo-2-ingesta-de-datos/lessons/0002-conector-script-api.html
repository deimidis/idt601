Lección 02 · Bloque 2 — Ingesta de Datos

Conector, script o API: ¿cuál elijo?

Al terminar, podrás elegir la herramienta de ingesta para cada caso y justificarla según la fuente, la transformación y el esfuerzo de mantenerla.

Esta es la otra mitad de la decisión: la lección 01 elige el método (batch o streaming); esta elige la herramienta. Ver referencia →

La pregunta que decide

Primero separa las dos decisiones: el método responde ¿cómo y cuándo movemos los datos? y la herramienta responde ¿con qué lo hacemos?. Para la herramienta, mira tres cosas: ¿la fuente es conocida o rara?, ¿necesito transformar a medida? y ¿el sistema ofrece un acceso estándar?.

Regla de oro: fuente conocida y repetida → conector; caso a medida o transformación propia → script; el sistema expone sus datos → API.

Practica: elige la herramienta

Elige una opción. Recibirás la corrección al instante.

1. Traer, sin escribir código, los datos de una hoja de cálculo compartida a un almacén.

Por qué: es una fuente conocida y repetida; una pieza ya hecha la resuelve sin programar.

2. Limpiar un CSV de recaudación con reglas propias (montos, fechas, duplicados) y cargarlo.

Por qué: hay transformación a medida; el script da control total, aunque hay que mantenerlo.

3. Leer los datos de clima de un servicio público que los expone de forma estandarizada.

Por qué: el sistema ofrece una puerta de acceso estándar; se consulta con su contrato (endpoints, claves).

4. Una fuente poco común para la que la plataforma no trae ninguna pieza hecha.

Por qué: si no existe conector y la fuente no expone API, se resuelve con código propio.

5. Necesito control total sobre qué se mueve y cómo se transforma en el camino.

Por qué: el script es flexible y a medida; el costo es programarlo y mantenerlo.

6. Que otro sistema me entregue sus datos de forma estandarizada y automatizable, sin leer archivos a mano.

Por qué: la API expone datos de un sistema para que otros los lean de forma controlada.

7. Lo que más importa al usar una API y hay que entender antes de conectar.

Por qué: una API exige comprender su contrato (qué pide, cómo se autentica y hasta dónde permite usar).
